## SECTION 3 — Technical Learnings (1:15 – 2:30)

**[SHOW: Code editor or tech stack slide in the background — can also show snippets while speaking]**

> "This internship was a massive learning experience for me on the technical side. Let me break down the key skills I gained.
>
> **React.js and Tailwind CSS** — I built the entire frontend with React, learning to think in components, manage state effectively, handle routing, and build responsive, accessible UIs. Tailwind CSS was a game-changer for me — the utility-first approach made styling so much faster compared to writing custom CSS.
>
> **Node.js and Express.js** — On the backend, I built a full RESTful API from scratch. I learned how to structure routes, write middleware, handle errors gracefully, and design APIs that are clean and scalable. Understanding the request-response lifecycle deeply — that was a big milestone for me.
>
> **PostgreSQL and Prisma ORM** — This was my first time using Prisma, and I was really impressed. Defining the database schema declaratively, running migrations, and writing type-safe queries — it's such a productive workflow compared to raw SQL. I also deepened my understanding of relational database design — setting up proper relationships, indexes, and constraints.
>
> **Authentication and Security** — I implemented **JWT-based authentication** from scratch — token generation, verification, refresh flows. I used **bcrypt** for password hashing, **Helmet.js** for securing HTTP headers, and built a complete **role-based access control** system. Security isn't just an add-on — it's foundational, and this project really drilled that into me.
>
> **REST API Design** — Designing a multi-role API with proper authorization boundaries taught me a lot about API architecture. Every endpoint needed to consider: who is calling it, what are they allowed to do, and what should they see?
>
> **File Uploads** — I used **Multer** to handle document and certificate uploads securely — validating file types, limiting sizes, and storing files properly."

## SECTION 4 — Challenges Faced (2:30 – 3:30)

**[SHOW: Your webcam, or relevant code snippets illustrating the challenges]**

> "Of course, no real project comes without challenges, and this one had several that pushed me to grow.
>
> The first major challenge was designing the **consultation booking system with availability conflict detection**. It's not just about picking a time slot — the system needed to prevent double-bookings, handle timezone considerations, and ensure that when a lawyer's slot is booked, it's immediately blocked for other clients. Getting the database queries and validation logic right for this took careful thought and multiple iterations.
>
> The second challenge was building a **role-based, multi-dashboard UI**. Three completely different user experiences — client, lawyer, and admin — all within the same application. Designing the component architecture so that shared components stay DRY while role-specific views stay clean and isolated was a real exercise in frontend architecture.
>
> Setting up **Prisma ORM with the PostgreSQL adapter** also had its learning curve. Configuring the connection, understanding Prisma's migration workflow, and debugging schema issues when models had complex relations — especially with cascading deletes and optional relations — required patience and careful reading of the documentation.
>
> And finally, **document upload security**. When users upload sensitive legal documents, you can't just accept any file. I had to implement proper file type validation, size limits, and secure storage patterns. Making sure uploaded files couldn't be accessed by unauthorized users was an important security consideration."
